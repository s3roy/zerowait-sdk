Your web screens are ready before they tap.

Zerowait is an SDK for native apps that show parts of themselves as web pages: checkout, a help centre, onboarding, a live stream, a video call. It loads your web app in the background with the user already signed in, then opens the screen in place instead of loading a page.

Where the wait comes from.

A web screen opened from scratch does four things after the tap. Zerowait moves each one before it.

  1. Start the browser engine

    The first WebView in your app starts Chromium or WebKit. On Android that alone can take more than a second.

    Zerowait

    Creates the WebView when your app goes idle after launch, long before anyone opens a web screen.

  2. Load your web app

    HTML, scripts, framework start-up and the first API calls, often over a mobile network.

    Zerowait

    Loads a page of your web app in the background with the user's cookies already set, and fetches the next route's code.

  3. Get to the right screen

    A full page load for every screen, even though the app is the same one.

    Zerowait

    Changes route inside the running app. Next.js works with no changes; any other framework needs one line.

  4. Leave cleanly

    Closing mid-request leaves calls running, orders held or drafts lost.

    Zerowait

    Runs your leave script, waits until its request has finished, then returns to the warm page for next time.

The parts you would otherwise debug in production.

Several pages, one memory budget
Keep checkout, help and live warm at once. A cap releases the least recently used idle page first, never the one on screen.
No leaked Activities
When a screen closes, the WebView is handed back to the app context and stays warm for the next time.
Recovers from renderer crashes
If the browser renderer dies, your app does not. Zerowait rebuilds the WebView and warms it again by itself.
Locked to your origins
The native bridge and camera access exist only for pages you trust. Anything else gets nothing, even if your app holds the permissions.
Signed in from the start
The user's session cookies are written before the first request.
Time to screen built in
Name the text that means "ready" and Zerowait reports when it first appears, with no change to your web app.
Local and offline pages
Serve bundled pages or an app shell from your APK for any route.
Video call module
A bundled WebRTC page, native signaling relay, call audio and stats for apps that need calls.

Three calls to wire it in.

  1. Register at launch

    Name the page, its warm URL and the cookies it needs.

  2. Prewarm

    On the next idle moment, so app start is not slowed down.

  3. Open

    From any screen, with the URL you want. The running app changes route.

Full quick start

// Application.onCreate
Zerowait.register(this, "checkout", WarmPageConfig(
    warmUrl = "https://shop.example.com/cart",
    cookies = listOf(PageCookie("session", token)),
))
Zerowait.prewarm(this, "checkout")

// When the user taps Checkout
Zerowait.open(this, "checkout", container,
    "https://shop.example.com/checkout?step=pay")
// AppDelegate, at launch
Zerowait.register("checkout", WarmPageConfig(
    warmURL: "https://shop.example.com/cart",
    cookies: [PageCookie(name: "session", value: token)]
))
Zerowait.prewarm("checkout")

// When the user taps Checkout
Zerowait.open("checkout", in: container,
    url: "https://shop.example.com/checkout?step=pay")
// Next.js: nothing to add.

// React Router, Vue, Angular, anything else: one line
window.__zerowaitNavigate = (path) => router.push(path)

Questions

Do I have to change my web app?

Not for Next.js. For other frameworks, add one line so Zerowait can change route: window.__zerowaitNavigate = (path) => router.push(path). Without it, screens still open faster because the browser engine is started and your app's files are cached, but each one loads as a page.

How much memory does a warm page use?

About as much as the same page open in a browser tab. Warm only the screens people are likely to open next, and set a cap: Zerowait releases the least recently used idle page first, and you can release idle pages when Android reports low memory.

Does prewarming cost data?

A hosted page downloads its files once in the background, as it would on first open. Bundled pages use no network. Nothing else runs until the user opens the screen.

What about users who aren't signed in yet?

Register the page after login, or call setCookies with the new session and prewarm then.

Does it include a video call backend?

No. The video call module relays signaling through a channel you provide, so it works with whatever you already run.

Which versions are supported?

Android 8.0 (API 26) and later with an up-to-date system WebView. iOS 15 and later.

Are the timings on this page from real phones?

They come from an Android 15 emulator, which is slower than most current phones. Absolute numbers on your devices will differ. The gap between cold and warm is what Zerowait removes.

How is the SDK delivered?

Add it from our Maven repository (Android) or with Swift Package Manager (iOS); see the install guide. After purchase you get a license key for your app ids, one line of code. The SDK is compiled, not source; the Enterprise plan includes source.

What does the license key do?

It is checked inside the app, offline, against your app id. Nothing is sent anywhere and nothing is ever blocked: without a valid key, release builds show a small "Zerowait · unlicensed" label on Zerowait screens.
